# Herdr Orchestration

Herdr Orchestration defines how Human policy, role authority, and runtime
capability become an enforceable multi-agent setup.

## Language

**Discovery Snapshot**:
An immutable observation of the project, repositories, harnesses, adapters,
and policy sources used to prepare a setup.
_Avoid_: Discovery result, environment dump

**Human Decisions**:
Typed policy, authority, model, and routing choices explicitly owned by the
Human.
_Avoid_: Wizard answers, inferred preferences

**Setup Candidate**:
An immutable proposed setup compiled from one Discovery Snapshot and its bound
Human Decisions; it is neither accepted nor published yet.
_Avoid_: Final config, completed setup

**Candidate Digest**:
The stable content identity of one exact Setup Candidate.
_Avoid_: Version, session ID

**Stale Candidate**:
A Setup Candidate whose bound Discovery Snapshot no longer matches current
discovery.
_Avoid_: Invalid config, old session

**Runtime Proof Receipt**:
An immutable evidence record bound to one Setup Candidate that states which
authority effects were observed and at what assurance.
_Avoid_: Smoke log, model report

**Setup Publication**:
An immutable pre-acceptance bundle containing the exact generated artifacts and
Runtime Proof Receipt for one Setup Candidate.
_Avoid_: Staging directory, accepted setup

**Acceptance Receipt**:
An immutable record that binds the Human's exact Candidate Digest confirmation
to one Setup Publication and its prior activation state.
_Avoid_: Approval message, success flag

**Activation Manifest**:
The single atomically replaced record that names the currently accepted
immutable setup generation.
_Avoid_: Current config, mutable pointer

**Setup Session**:
A resumable project-local record of one Discovery Snapshot identity, typed Human
answers, and canonical proof/acceptance receipts.
_Avoid_: Conversation memory, wizard transcript

**Setup Revision**:
The compare-and-swap identity of the current Setup Session state used when
submitting typed Human answers.
_Avoid_: Candidate version, step number

**Typed Setup Question**:
An unresolved decision generated by the Setup Engine with an exact identifier,
value kind, feasible options, and provenance-bearing facts.
_Avoid_: Presenter question, LLM suggestion

**Setup View**:
The pure Human-facing projection of one Setup Session and its current engine
result; it contains no decision added by the presenter.
_Avoid_: Chat response, mutable setup state

**Binding**:
One adapter-specific implementation of a role's effective authority envelope.
_Avoid_: Recipe, role

**Accepted Project**:
One project whose active immutable setup generation and Human acceptance chain
have been verified as a single runtime authority.
_Avoid_: Current config, mutable setup

**Runtime Role Template**:
The accepted logical authority and model binding for one role before any exact
Assignment paths are supplied.
_Avoid_: Recipe, proof launch spec

**Bound Role Launch**:
One Runtime Role Template compiled with the exact paths for one Assignment into
a single native launch contract and content identity.
_Avoid_: Selected binding, role config
